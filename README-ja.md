# namiyomi ver 0.2.0

**AB1の波形確認から、トリミング、コンティグ作成、配列編集、FASTA出力まで。**

namiyomiは、日常的なサンガーシーケンスの確認作業に用途を絞ったデスクトップアプリです。**機能はこの作業に必要な最小限に絞っている**ため、使い始める前に設定することや覚えることがほとんどありません。コンセンサス配列と、その根拠となるクロマトグラムを同じ画面で確認できます。組み立てと編集は端末内で行います。オンラインAIレビューは任意です。アプリとソースコードはMITライセンスで無償公開しています。

## できること

- ファイル名の規則に依存しないAB1の取り込み。
- 取り込み時の自動末端トリミングと、左右の手動カット。
- 選択した2本以上のリードからのコンティグ作成と、整列した波形の表示。
- 元リードの編集に応じたコンセンサスとSupport Qの再計算。
- レビューフラグ、塩基編集、逆相補、Undo/Redo、配列・FASTAのコピー。
- 両鎖に対応した配列検索。完全一致のほか、80～100%の一致率を設定可能。
- 編集可能なプロジェクトの保存、ローカルの復旧用スナップショット、FASTA出力。

クローニング設計、制限酵素地図、BLAST、系統解析、ゲノム規模のアセンブリは含めていません。AB1を開いてから、確認した配列を取り出すまでの作業に集中できます。アプリの利用にアカウントやクラウドサービスは必要ありません。

## デモを試す

両OSの配布ZIPには、人工的に生成した4本のAB1と、作成済みの`Demo.json`を含む`demo`フォルダを同梱しています。リポジトリの[`demo`](demo)にも同じファイルがあります。配列と波形はデモ用の合成データであり、**生物試料に由来する観測値や装置の実測データではありません。**

`demo`内のファイルを一緒に保ち、**File > Import Previous Project**から、展開した配布フォルダの`demo/Demo.json`を開いてください。コンティグの確認、Find検索、塩基編集とUndoを試せます。練習した内容は**Save Project As**で別ファイルへ保存できます。最初からコンティグを作る場合は、新規プロジェクトに4本のデモAB1を取り込んでください。

## 基本的な使い方

1. **AB1を取り込む。** **File > Import AB1**を選ぶか、ファイルをウィンドウへドラッグします。取り込んだリードは**AB1 files**に個別に並びます。この段階では、自動グループ化もコンティグ作成も行いません。末端の自動トリミングは初期設定で有効です。条件を変える場合は、取り込み前に**Settings > Trimming Settings**を開きます。
2. **波形とトリミング位置を確認する。** グレーの範囲は出力から除外されます。右下の**Base spacing**と**Trace height**で横幅と波形の高さを調整できます。追加のカットには**Edit > Cut Left / Cut Right**を使います。
3. **同一個体・同一領域のリードを選ぶ。** Shiftキーを押しながら必要なリードを選び、**Assembly > Build Contig (manual)**を実行します。3本以上にも対応しています。アセンブリは両方向を調べるため、ファイル名やプライマー名から向きを決める必要はありません。
4. **コンセンサスを確認・編集する。** フラグの位置を波形と照合します。塩基をクリックして入力すると置換でき、Backspaceで選択した塩基を削除できます。元リードの編集はコンセンサスへ反映されます。確認したフラグには**Review > Mark Reviewed**を使います。この操作は確認済みであることを記録するもので、品質値を上げるものではありません。
5. **保存・出力する。** **Save Project**は初回に保存名を尋ね、以後は同じファイルへ上書きします。**Export Project Copy**は、現在の保存先を変えずに別コピーを作ります。リードまたはコンティグを選んでFASTAを出力できます。右クリックの**Copy FASTA**は、選んだ配列をFASTA形式でクリップボードへコピーします。

コンティグを作り直す場合は、右クリックから**Return Reads to AB1**を選びます。元リードの編集とトリミングは残ります。削除するコンティグだけに加えた編集やレビューフラグは元リードへ転写されません。操作全体はUndoで戻せます。

### ファイル名を利用したAUTOアセンブリ

**Assembly > Build Contig (AUTO)**は、元のAB1ファイル名の最初の`_`より前を使って、未使用リードをグループ化します。たとえば`sample07_forward.ab1`と`sample07_reverse.ab1`は`sample07`としてまとめられ、成功したコンティグにはその名前が付きます。

AUTOは、各接頭辞が「同一個体の同一領域」を表す場合だけ使用してください。既存コンティグで使われているリードは対象から外れ、手動作成済みのコンティグも再構築しません。命名規則が異なるデータにはmanualを使います。1本だけのグループからもコンティグを作れますが、複数リードによる独立した裏付けにはなりません。

### AI Reviewで塩基を確認する

**AI Review** は、フラッグが付いた箇所を波形と照合して、どこを人が確認すればよいかを絞り込む機能です。

1. **まず、端末内で波形を確認する。** **AI Review > Review Start** を開きます。未使用のリードがあればAUTOと同じ規則で組み立て、フラッグの付いた箇所を波形と照合します。波形から明確に判断できる場合は、塩基を修正したり、余分に読み取られた塩基を削除したりします。初期設定の **This device only** はAPIキーなしで使えます。
2. **残った箇所をAIにも確認させる（任意）。** レビューの前に **AI Review > Settings** で OpenAI、Claude、Gemini のいずれかを選び、APIキーを設定します。AIが自信を持って答え、波形からも裏付けられる場合にだけ、その判定を反映します。手動で編集した箇所や、二重ピークを示すIUPACコードは上書きしません。

   AIに送るのは、確認箇所の前後の塩基、品質スコア、短い区間の波形を数値にしたデータです。AB1ファイル、波形画像、試料名は端末に残ります。
3. **レポートから波形を開く。** **AI Review Report** の **Flags** は、確認が残っている箇所の数です。コンティグ名をクリックすると、確認箇所に移動します。同じ名前をもう一度クリックすると、次の赤フラッグに進みます。

![端末内レビューを選んだAI Reviewの設定画面。](docs/images/namiyomi-ai-settings-macos.jpg)

![同梱デモのAI Review Report。Flags列で残りの確認箇所が分かります。](docs/images/namiyomi-ai-report-macos.jpg)

- **赤フラッグ**は、AIに確認しても修正が確定しなかった箇所です。
- **黒フラッグ**は、AUTOで付いた印です。自動で解決した箇所にも履歴として残り、その箇所は **Flags** の件数から外れます。
- **青緑の下線**は、自動判定を反映した箇所です。

**Edit > Undo** で、組み立てとレビューをまとめて取り消せます。[波形の判定ルール（英語）](docs/TRACE_REVIEW.md)

### ターミナルでAB1ファイルをまとめて処理する

AB1ファイルがたくさんあるときは、コマンド一つで末端をトリミングし、試料ごとに組み立てて、FASTAに出力できます。たとえば `sample07_F.ab1` と `sample07_R.ab1` は、最初の `_` より前が同じなので、一つのグループになります。接頭辞は同じ試料・同じ領域のファイルにだけ使ってください。ファイル名で区別できないときは、CSVでグループを指定できます。

**同梱デモで試す**には、Python 3.10以降を用意し、ソースコードZIPを展開します。ターミナルで、`README.md` があるフォルダを開き、次の2行を順に実行します。環境によっては `python` を `python3`（Mac）または `py -3`（Windows）に置き換えてください。[v0.2.0のソースコードZIP](https://github.com/yoneoka-katsuhiro/namiyomi/archive/refs/tags/v0.2.0.zip)

```sh
python -m pip install -r requirements/batch.txt
python src/batch.py --input demo --output demo-results
```

1行目は初回だけです。自分のデータを処理するときは、`demo` をAB1ファイルの入ったフォルダに、`demo-results` を新しい出力フォルダ名に置き換えます。元のAB1ファイルはそのまま残ります。

`demo-results` には次のファイルが入ります。

- **`auto.fasta`**：デモで組み立てた配列。
- **`project.json`**：namiyomiの **File > Import Previous Project** で開くと、波形を確認できます。
- **`summary.tsv`**：組み立て結果と、確認が必要なコンティグの一覧。

コマンドの末尾に `--review` を足すと、端末内でフラッグの位置を波形と照合し、判定を `review.tsv` に記録します。ここまでの操作にAPIキーやMCPは不要です。CSVでのグループ指定やオンラインAIの使い方は、[一括処理ガイド（英語）](docs/BATCH.md#command-line)にあります。

### MCPクライアントから確認・トリムする

これは **AI Review** とは別の機能です。AI Reviewを使うのにMCPは必要ありません。違いを下の表にまとめます。

| | **AI Review**（アプリのメニュー） | **MCPレビューサーバー** |
| --- | --- | --- |
| 確認する主体 | namiyomiのローカル規則。続いて、必要なら **ご自身のAPIキー** でOpenAI・Claude・Gemini | Claude CodeやClaude Desktopなど、すでに使っているMCPクライアント。namiyomiにAPIキーは不要 |
| 使い方 | アプリで **AI Review > Review Start** をクリック | クライアントとの会話で依頼する（例：「このリードをnamiyomiで処理して、フラッグを確認し、末端をトリムして」） |
| AIモデルが見るもの | 各フラッグ付近の塩基、クオリティ値、数値化した波形の抜粋 | 配列、ファイル名、波形画像（下記のツール経由） |
| 準備 | 不要 | `pip install -r requirements/mcp.txt` を実行し、`src/mcp_review_server.py` をクライアントに登録 |
| 結果 | プロジェクトに記録され、アプリに表示される | 同じ。新しいプロジェクトファイルに保存され、アプリで開ける。クライアントが判断を保留したフラッグは赤で表示 |

アプリ内で手早く確認したいときはAI Review、会話しながらリードを扱いたいとき（フォルダの一括処理、個々の波形の確認、指定した規則での末端トリム）はMCPサーバーが向いています。どちらも、はじめにローカルの波形規則で明確な箇所を処理します。

1. **インストール**（初回のみ）：`python -m pip install -r requirements/mcp.txt`
2. **クライアントにサーバーを登録する。** Claude Codeの場合：
   ```sh
   claude mcp add namiyomi-review -- /path/to/python /path/to/namiyomi/src/mcp_review_server.py
   ```
   ほかのクライアントも、MCP設定に同じコマンドと引数を指定します。
3. **フォルダの処理を依頼する。** まだ存在しない出力フォルダを指定してください。一括処理、フラッグ付き波形の確認、末端トリムの提案ができます。トリムの規則に同意するまで、何も変更しません。
4. **結果を開く。** 編集は新しい `project.reviewed.json` と `review_report.md` に保存され、元のプロジェクトとFASTAは変更されません。**File > Import Previous Project** で開きます。列番号はアプリと同じく1から数えます。

サーバー自体は通信を行いませんが、接続したクライアントは求めた配列や波形画像を見られます。データを任せてよいクライアントにだけ登録してください。小さい方の `src/mcp_server.py` は別物で、匿名の品質件数を返すだけで、編集や出力はできません。ツールの一覧は[一括処理ガイド（英語）](docs/BATCH.md#review-and-trim-from-an-mcp-client)を参照してください。

### 配列を検索する

![Find欄へ入力した配列と、その逆相補に一致する場所をオレンジ色で表示した画面。使用データは合成デモです。](docs/images/namiyomi-find-macos.png)

*Findはコンセンサスの両鎖を検索します。一致箇所はオレンジ色で表示されます。画面の配列と波形はデモ用の合成データです。*

初期設定は完全一致です。**Settings > Find Settings**で、80～100%の一致率へ変更できます。類似検索は塩基の置換だけを対象とし、ギャップは考慮しません。IUPAC文字は文字どおりに照合し、ワイルドカードとしては扱いません。編集・挿入した塩基は検索に含まれ、削除した塩基は含まれません。矢印ボタンかEnter / Shift+Enterで一致箇所を移動でき、Escで検索を解除できます。検索によって配列が変わることはありません。

## 他のソフトとの使い分け

namiyomiの役割は1つです。AB1の波形を確認し、コンティグを作り、波形を見ながらコンセンサスを直して、FASTAで出力します。ほかのソフトは大きく4種類に分かれます。namiyomiと並べて、それぞれにできること・できないことを示します。

| ソフト | 対応OS | できること | できないこと |
| --- | --- | --- | --- |
| **namiyomi** | macOS（Apple Silicon、15以降）<br>Windows 10/11（x64、試験版） | Sangerのアセンブリと編集。手動または自動でのコンティグ作成。必要最低限に絞った、直感的でわかりやすい設計で、研究・教育での利用にも最適化しています。 | NGSリードのアセンブリや参照配列へのマッピングなど、複雑な操作はスコープ外です。 |
| **有償のSanger解析ソフト** | **Sequencher：** Windows（現行版は64-bitのmacOSに非対応）<br>**Geneious Prime：** Windows、macOS、Linux<br>**ChromasPro：** Windowsのみ | Sangerのアセンブリと編集に加え、より広い解析（製品により、ヘテロ接合・変異の検出、参照配列へのマッピング、クローニング支援、NGS）、名前のルールを設定できる一括アセンブリ（複数の製品）、開発元のサポート。 | 通常の研究利用では無償で使えません。購入または年額のライセンスが必要です。また、多数の汎用ツールの中から、必要な操作を選んで使う必要があります。 |
| **無償の波形ビューア** | **Chromas：** Windowsのみ | 1本の波形の表示、編集、トリミング、検索、出力。 | リードを組み立ててコンティグを作れません。開発元は、その用途には有償のChromasProを案内しています。 |
| **無償の統合解析ソフト** | **UGENE：** Windows、macOS、Linux | Sangerリードの編集画面やCAP3によるアセンブリを含む、多数の解析ツール。 | Sangerの確認作業専用ではありません。多数の汎用ツールの中から、必要な操作を選んで使う必要があります。 |
| **Rやコマンドラインのツール** | **sangeranalyseR：** R上（Windows、macOS、Linux）<br>**Tracy：** macOS、Linux（Bioconda、Homebrew、コンテナ） | スクリプトによる再現可能な一括処理とレポート出力。 | Rやコマンドラインを使わずには利用できません。波形を見ながら1塩基ずつ修正することもできません（sangeranalyseRの説明では、手動の修正は別のソフトで行うよう案内しています）。 |

ほかのソフトにしかない機能が必要な場合は、そちらを選んでください。namiyomiは、これらのソフトと速度や精度を比べるベンチマークは行っていません。各ソフトの機能、対応OS、ライセンスは、開発元の資料へのリンク付きで[詳しい比較表](docs/COMPARISON-ja.md)にまとめています。

## 制約とデータの取り扱い

- **対象は小規模なサンガーコンティグです。** アセンブリはgreedy overlap方式です。初期条件は、比較可能な塩基が100以上の重複と90%以上の一致率です。反復配列の解決やゲノムアセンブリには適していません。ファイル名や配列の重なりだけで、個体・領域・コンタミネーションの有無は判定できません。
- **Support Qは、統計的に統合された確率ではありません。** 自動コールを支持する、使用可能な元のPhredの最大値です。高品質な塩基の不一致や内部ギャップは`N`とフラグで残る場合があります。手動編集した塩基に装置由来の品質値は付きません。
- **向きの統一は相対的なものです。** 類似する既存コンティグのうち、先に作ったものを基準に向きを揃えます。遺伝子の生物学的な正方向を判定する機能ではありません。
- **プロジェクトJSONだけでは波形を持ち運べません。** JSONはAB1のパスとチェックサムを保存し、波形自体は埋め込みません。元のAB1は変更しません。別のPCへ移すときは、参照先のAB1と相対的なフォルダ構成も一緒に保ってください。AB1が見つからない、または内容が変わった場合は、プロジェクトを開けないことがあります。
- **復旧用スナップショットはバックアップの代わりではありません。** 未保存の変更は約30秒ごとに端末内へ記録しますが、異常終了の直前の編集やUndo履歴は失われる可能性があります。通常の保存とバックアップを併用してください。
